## 1. 里程碑规划

里程碑顺序不可调换：M1 是 M2 的数据地基（没有结构化记录就没有计划执行证据），M2 是北极星指标成立的前提。每个里程碑启动前，其覆盖 FR 须全部「已评审」（见 README §2.6，FR-H0 例外先行）。

| 里程碑 | 版本 | 目标（一句话） | 包含 FR | 完成定义（DoD） |
|---|---|---|---|---|
| M0 技术债清偿 | v1.0.1 | 让现有产品真正可用 | H0 | TypeScript 编译零错误；真机走通"匿名登录→记录→列表→图表"全链路；RLS 插入不再被拒 |
| M1 记录闭环 | v1.1 | 记录从流水账升级为适应度观察 | A1–A3、D1–D4、E1–E3、F1/F3、H1/H2/H4、G1 | 记录+打卡闭环可用；微信登录迁移无损；埋点就位（glossary §5 指标全部可统计）；隐私政策上线 |
| M2 计划闭环 | v1.2 | 解决"怎么转奶"——产品核心成立 | B1/B2、C1–C7、D5、A4、I1、F2、G2 | 北极星可统计（完成判定按 00-glossary §3 执行）；计划完成率 ≥ 60%（小样本）；医学规则审核记录留档 |
| M3 决策闭环 | v2.0 | 解决"怎么选奶粉" | B3、G3、I2/I3 | 问卷上线且采纳率可统计；分享卡带来新增（L4 可归因） |
| M4 演进 | v2.x+ | 按数据决策 | H3、B4、及 §2 解锁项 | 各项回评审通过 |

## 2. 范围管理：本期明确不做（防蔓延清单）

> 列入此处不是"永远不做"，而是**当前证据不支持投入**。每项带重新评估条件，满足时回评审立项。

| 事项 | 不做的理由 | 重新评估条件 |
|---|---|---|
| 电商/带货/比价购买 | 合规重（母乳代用品销售限制），与工具定位冲突 | 稳定月活与品牌方合作意向 |
| UGC 社区/问答 | 审核成本高，医学内容风险不可控 | 专业顾问团队就位 + 审核流程建立 |
| AI 答疑（症状问答） | 医疗合规风险；无顾问背书前不上线 | NFR-1 审核机制覆盖 AI 输出 |
| 身高/头围生长曲线 | 与转奶闭环关联弱（体重保留，因其直接服务适应度判断） | 用户调研强烈要求 |
| 奶粉评分/排行榜 | 中立性风险，与产品原则 4 冲突 | 不适用（原则性排除） |
| 完整离线同步 | 小程序场景弱网可提示重试，复杂度高收益低 | 弱网投诉成为 Top 问题 |
| H5/RN 多端 | 提醒等核心能力依赖微信生态，多端稀释投入 | 微信端留存验证成功后 |
| 反馈/客服入口 | 初期"关于我们"内邮箱够用，自建通道成本高 | 用户反馈量成为运营负担 |

## 3. 风险与对策

| 风险 | 影响 | 对策 | 归属 |
|---|---|---|---|
| 医学规则不当引发误导 | 严重（信任与合规） | NFR-1 顾问审核 + 配置化阈值 + 保守措辞 + 免责声明 | 全局 |
| 微信订阅消息送达不稳定 | 提醒失效 | 应用内提醒为主、订阅消息为增强（FR-I1 设计前提） | I |
| 用户打卡惰性，数据不足 | L2 失效 | 输入成本原则（3 秒记奶/30 秒打卡）+ 漏记提醒 + 数据不足时友好降级（E3） | D/E |
| 奶粉库冷启动不全 | 计划创建受阻 | 首批 ≥50 SKU + 手动输入品牌兜底路径（FR-C1/B2） | B/C |
| 匿名→微信数据迁移出错 | 老用户数据丢失（不可逆） | 迁移幂等可重试、失败不落库、灰度放量（FR-H1 验收标准） | H |
| 内容合规（广告法/特医奶粉） | 处罚风险 | G2 合规专栏 + 运营发布审核流程 + 中立呈现原则 | G |
