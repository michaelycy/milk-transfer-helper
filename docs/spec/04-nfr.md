# 04 · 非功能需求（NFR）

| 元素 | 内容 |
|---|---|
| 文档状态 | 草案（随 v2.0-draft2 拆分） |
| 上游文档 | [README.md](README.md) |
| 约束范围 | 全部模块；与功能需求冲突时以 NFR-1/NFR-2 为最高优先 |

## NFR-1 医学安全与内容合规 `最高优先级`

- 所有医学类规则默认值（FR-C2 转奶模板、FR-C6 安全规则、FR-E1 预警阈值、FR-D3 大便图卡、FR-F3 奶量参考量）**上线前须经儿科医生/注册营养师审核**，审核版本与日期留档；阈值调整走配置表并重新走审核。
- 全部输出为"提示与记录工具"，不含诊断、疗效、用药建议；预警与问卷结果固定附免责声明。
- 内容遵守《广告法》对母乳代用品宣传的限制：不出现品牌推荐/排名/绝对化用语；"我的"页与文章页固定免责声明入口。

**验收标准**
- [ ] 每条医学规则有对应审核记录（顾问、日期、版本）；
- [ ] 全局检索无"治疗/治愈/最有效"等违规表述的构建期检查（文案表 lint）；
- [ ] 红色预警文案不可被配置为"可忽略"。

## NFR-2 隐私与数据合规

- 宝宝数据属敏感个人信息（未成年人）：建档前展示并取得单独同意的隐私政策；
- 数据最小化：不收集宝宝照片、真实姓名、精确位置（FR-A1 已约束字段）；
- 支持账号注销与数据级联删除（FR-H2）；用户数据隔离一律依赖 RLS（沿用 `auth.uid()` 模式，新表同规则）。

**验收标准**
- [ ] 建档流程含单独同意步骤且留痕（同意时间 + 政策版本）；
- [ ] 注销后业务表无残留数据（抽样校验脚本）；
- [ ] 隐私政策变更时重新征集同意。

## NFR-3 性能

- 首屏可交互 ≤ 2s（常规网络）；记录提交 P95 ≤ 1s；预警评估在打卡提交后同步完成（用户可即时看到结果）。
- 弱网下提交失败有明确提示与本地草稿保留（不做完整离线同步，见 02-roadmap §2）。

**验收标准**
- [ ] 真机测试报告覆盖低端安卓机型；
- [ ] 记录提交失败时表单数据不丢失（重进可恢复）。

## NFR-4 兼容

- 微信基础库最低版本策略在技术文档中声明并随版本更新；
- iOS 日期解析兼容：**禁止裸 `new Date('YYYY-MM-DD HH:mm')`**，一律复用 `src/utils/date.ts` 的手动解析；
- iPhone SE 小屏与主流安卓分辨率适配。

**验收标准**
- [ ] 构建期 lint 禁止裸日期解析模式；
- [ ] 375×667 小屏下核心页面无截断（设计画板 375×812 基础上验收小屏）。

## NFR-5 可维护性

- 分层不变：`pages → services → supabase`；纯逻辑（计划逐日生成、规则评估、聚合统计）沉淀为 `utils` 纯函数并配单元测试（延续 `date.test.ts`/`chart.test.ts` 模式）。**计划引擎与规则引擎必须有单测覆盖**。
- 数据库变更一律走 `supabase/migrations/` 增量文件（规范见 03-data-model §4）。
- 类型安全：新表生成 `src/types/database.ts` 类型，服务层禁止 `any`。
- 文档同步：需求变更 → docs/spec；技术方案 → tech-arch 文档，二者在里程碑 DoD 中检查。

**验收标准**
- [ ] 计划生成、回退计算、预警规则纯函数单测覆盖率 ≥ 90%（分支覆盖）；
- [ ] CI（或本地脚本）跑通：tsc + 单测 + 迁移 lint。

## NFR-6 可用性

- 核心按钮 ≥ 44px；快速记录入口在拇指热区（右下）；
- 空状态必有引导动作（去哪里、做什么）；
- 预警级别不依赖纯颜色传达：红/黄/绿须配图标与文字（色觉障碍友好）；
- 关键操作（删除记录、回退计划、注销）均有二次确认并明示后果。

**验收标准**
- [ ] 设计走查清单：44px、热区、空状态、色觉四项逐页核对；
- [ ] 所有破坏性操作清单化复查。
