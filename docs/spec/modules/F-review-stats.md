# 模块 F · 统计与复盘

| 元素 | 内容 |
|---|---|
| 文档状态 | 草案 |
| 所属闭环 | L2 输出 + L4 分享源 |
| 上游依赖 | D 记录、C 计划、A 档案（FR-A3 体重） |
| 下游被依赖 | L4 增长（分享卡）、下一次转奶决策（复制计划） |
| 覆盖需求 | FR-F1 ~ FR-F3 |
| 数据表 | 只读聚合 `feed_records` / `transfer_plans` / `alerts` / `weight_logs`（见 [03-data-model.md](../03-data-model.md)） |

## 1. 模块定位

闭环的"收口"：把一次转奶的过程数据变成结论（成功了吗、出过什么问题、奶量怎么变化），并输出两个资产——**可复制的经验**（复制为新计划）与**可传播的凭证**（脱敏分享卡，L4 增长入口）。对 P3 画像（过敏宝宝妈妈），复盘报告是复诊时与医生沟通的材料。

## 2. 需求明细

### FR-F1 趋势图表升级 `P1`｜依赖：D1/D2、H0｜闭环：L2
- 描述：在现有日奶量折线（`src/utils/chart.ts` 的 `buildDailyTrend`）基础上升级，按里程碑拆分交付：**M1**——按配方分段着色、时间范围切换（7/30 天）；**M2**——转奶期间叠加新奶占比（依赖 FR-D5 计划关联）。日聚合统一按喂养日（00-glossary §2）。
- 验收标准：
  - [ ] 纯函数聚合逻辑有单元测试（延续现有 `chart.test.ts` 模式）；
  - [ ] 空数据与单条数据不崩。

### FR-F2 计划复盘报告 `P1`｜依赖：C4、D5、F1｜闭环：L2/L4
- 描述：计划终态（完成/终止）生成复盘：实际天数、偏离次数、预警次数与处理、奶量变化、体重变化（有数据时）。支持生成**脱敏分享卡**（不含宝宝姓名/照片，本产品也不收集）。复盘摘要同时反哺计划向导的历史经验展示（FR-C1）。
- 验收标准：
  - [ ] 报告可作为就医沟通材料保存图片；
  - [ ] 分享卡带小程序码与中性文案，无品牌倾向（NFR-1/产品原则 4）；
  - [ ] 报告数据全部来自落库数据，不依赖前端内存态；
  - [ ] 分享卡小程序码携带归因参数 `scene=share_plan`，新用户首次启动记录来源（落地为 FR-H4 的 `app_launch(scene)` 事件）。

### FR-F3 奶量参考对照 `P1`｜依赖：A3、D1/D2｜闭环：L2
- 描述：按**月龄分档**估算每日总奶量参考区间（档位定义见 00-glossary §1 纯奶期/辅食期）：纯奶期（0–6 月）按体重约 150ml/kg/天（设上限）；辅食期（6–12 月、12 月+）按总奶量区间。全部档位数值经顾问审核后固化为配置（NFR-1）。
- 验收标准：
  - [ ] 档位由月龄自动判定，辅食期不再使用 ml/kg 公式（防止系统性高估）；
  - [ ] 无体重且处于纯奶期时，用月龄中位体重估算降级，不隐藏不报错；
  - [ ] 明示"参考区间，非标准，有疑虑咨询医生"；
  - [ ] 参考参数存配置表（NFR-1 审核后可调）；该参考同时作为 FR-E1 奶量规则的基数。
