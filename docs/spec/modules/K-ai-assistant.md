## 1. 模块定位

AI 在本产品中的角色是**「输入加速器 + 数据解读器」**，不是泛育儿聊天机器人（产品定位与原则 4 的边界不变）：

- **输入加速**（FR-K2/K3）：把物理世界（奶瓶刻度、奶粉罐）变成结构化数据，直接服务「输入成本最小化」原则（原则 3）；
- **数据解读**（FR-K4/K5）：把已有记录变成可执行建议，但**医学结论一律由既有规则引擎（FR-E1）裁决**，AI 只产出结构化观察，不绕过 NFR-1 审核链。

**红线（一票否决）**：
1. AI 输出不构成诊断、疗效、用药建议（NFR-1）；便便评估的预警级别由 FR-E1 规则引擎产出，AI 仅提供「颜色/性状/疑似异常」的结构化观察；
2. 模型供应商密钥只存在于后端环境变量，任何配置表、日志、客户端均不落 key（NFR-2 / 模块 J 安全模型）；
3. 照片最小化：拍照数据**默认分析即弃**，不落库；用户显式选择保留时才上传私有存储（NFR-2，修订条款见 [04-nfr.md](../04-nfr.md)）；
4. AI 故障不得阻塞主链路：识别失败一律降级为既有手填路径（记录永远第一公民）。

02-roadmap §2 原列入「不做清单」的「AI 答疑」，其重新评估条件（NFR-1 审核机制覆盖 AI 输出）由 FR-K1 的提示词审核机制满足，已随本模块立项移出不做清单。

## 2. 需求明细

### FR-K1 AI 配置与安全网关 `P0`｜依赖：J6（配置载体）、H0（会话）｜闭环：L1–L3（全部能力的前提）

- 描述：后端 AI 网关，四个 AI 场景（`chat` 问答 / `poop` 便便 / `bottle` 奶瓶 / `can` 奶粉罐）各自独立配置与限流：
  - **场景配置**（`ai_configs`，管理端 FR-J6 维护）：provider、模型名、base_url（zhipu/openai 可省略，**自定义供应商必填**，OpenAI 兼容协议）、temperature、max_tokens、每用户每日限额、场景开关；供应商接入为配置驱动——任意 OpenAI 兼容供应商即可新增，无需改代码；**密钥界面化设置（v2.0-draft7）**：管理端录入后以 AES-256-GCM 加密落库（`ai_provider_secrets`，主密钥在环境变量），编辑不回显（仅末 4 位掩码）；网关解析优先级 = 库内密文 > 环境变量 `AI_<PROVIDER大写>_API_KEY`（兜底），明文只在后端内存瞬时存在；
  - **提示词模板**（`ai_prompt_templates`，版本化）：每场景 system prompt，支持变量插值（`{baby_nickname}` `{baby_age_months}` `{plan_day_label}` `{current_formula}`）；**四场景均预置默认草稿**（种子为 `pending` 未启用），管理端可「依此编辑」为新版本，经顾问审核（`review_status: pending → approved`）并启用后生效，**仅 approved 且 enabled 的版本可生效**（NFR-1）；(scene, version) 唯一索引兜底并发；
  - **输出安全护栏**（纯函数 + 单测）：模型输出含红线词（诊断/用药/疗效承诺类）时整体替换为固定引导文案；用户输入含高危症状词（血、发热、抽搐等）时在回答前置固定就医提示；
  - **配额与记账**：`ai_usage_logs` 记每次调用（场景/成败/tokens）；超限返回固定降级文案；全局开关关闭时所有场景直接降级；
  - **兜底降级**：模型超时/不可用/返回不合法时，按场景返回固定文案并引导既有路径（问答 → 站内文章；识别 → 手填表单）。
- 验收标准：
  - [ ] 任何响应、日志中不出现供应商密钥明文与密文；数据库仅存 AES-256-GCM 密文与末 4 位掩码（代码检索 + 测试断言）；
  - [ ] 场景开关关闭 / 超限 / 模型不可用三类降级路径均有固定文案且不抛裸错误；
  - [ ] 未 approved 的提示词版本即使 `enabled` 也不生效（服务端强制）；
  - [ ] 护栏为纯函数，红线词表与高危词表有单测覆盖全部分支；
  - [ ] 网关对上游超时（≤15s）有处理，用户侧等待时间不超过 20s。

### FR-K2 拍奶瓶快速记奶 `P1`｜依赖：K1、D1｜闭环：L1/L2（输入加速）

- 描述：拍照/选图 → 视觉模型识别瓶身刻度奶量 → **预填**快速记录表单（金额、时间自动带入）→ 用户确认提交（AI 不自动写入）。识别失败或低置信度（<0.6）时直接进手填表单，不重复尝试。入口：AI 助手页「拍奶瓶记奶」。
- 验收标准：
  - [ ] 从进入页面到提交成功 ≤ 15s（识别 ≤ 8s + 确认 ≤ 7s），失败路径回退手填不丢失已拍照片供人工参考；
  - [ ] 识别结果必须经用户确认后才写入 `feed_records`（不自动提交）；
  - [ ] 照片默认不上传存储：仅 base64 随识别请求即时分析，请求完成即弃；
  - [ ] 每用户每日识别次数受 `ai_configs.daily_limit_per_user` 限制，超限给出手填引导。

### FR-K3 拍奶粉罐识别 `P1`｜依赖：K1、B1/B2、C1｜闭环：L3（数据飞轮）

- 描述：拍照/选图 → 视觉模型识别品牌/系列/段位 → 与奶粉库匹配（品牌模糊 + 段位精确）：
  - **命中**：展示奶粉库卡片（中性呈现，无推荐语），可进入搜索结果或带品创建计划（FR-C1 向导）；
  - **未命中**：引导提交补录（`milk_product_submissions`，含识别 payload 与可选照片），运营在管理端处理（FR-J6 同队列服务 FR-B4 条码补录）；
  - 同一识别结果命中库内 SKU 时直接返回库内数据（缓存效应），不重复调模型。
- 验收标准：
  - [ ] 命中展示卡片与 FR-B2 搜索结果卡同构（蛋白类型/注册号标注、中性口径）；
  - [ ] 未命中提交后用户可见「已提交，运营会尽快收录」状态；照片仅在用户勾选「附上照片帮助补录」时上传私有存储（路径含 user_id，RLS 隔离）；
  - [ ] 补录队列条目在管理端处理后状态流转 `pending → processed / dismissed`。

### FR-K4 便便拍照评估 `P2`｜依赖：K1、D3、E1/E2｜闭环：L2（观察加速）

- 描述：拍照 → 视觉模型输出**结构化观察**（颜色/性状/疑似异常 + 置信度 + 中性描述）→ 映射到 FR-D3 打卡草稿（便便三要素：次数不变、性状/颜色预选）→ 用户确认/修正后按既有打卡链路保存 → **由 FR-E1 规则引擎判定预警级别**（AI 结果不直接产生预警）→ 命中时走既有预警呈现（FR-E2，含就医建议与免责声明）。页面固定展示：「AI 观察仅供参考，不构成医学判断；异常或持续异常请及时就医」。
- 验收标准：
  - [ ] AI 输出 schema 固定为 `{color, texture, abnormal_suspect, confidence, note}`，无自由结论字段；`note` 为中性观察描述，经护栏校验；
  - [ ] 预警级别只能来自 `evaluateSymptoms`（FR-E1 纯函数），页面不因 AI 结果直接展示红/黄/绿结论；
  - [ ] 照片默认不留存（同 FR-K2）；分析结果（不含照片）落 `ai_analyses` 供用户回看；
  - [ ] 低置信度（<0.6）时明确提示「识别不确定，请以人工打卡为准」；
  - [ ] 免责声明固定展示，不可关闭（NFR-1）。

### FR-K5 限定域问答 `P2`｜依赖：K1、A 档案、C 计划、G1｜闭环：L1/L2/L3

- 描述：AI 助手对话页。限定域：转奶方法、奶粉知识、喂养观察解读；出域问题（疾病问诊、辅食食谱等）礼貌拒答并导流站内文章/就医提醒。回答注入宝宝上下文（昵称、月龄、当前奶粉与蛋白类型、进行中计划第几天），上下文不足时降级为通用回答并提示建档可更精准。回答末尾按内容附动作入口（「去打卡」「查看预警」「查奶粉库」）。
- 验收标准：
  - [ ] 会话历史落 `ai_chat_messages`（own RLS），用户可清空；历史注入对话（最近 N 轮）可关闭；
  - [ ] 出域问题识别命中时返回固定引导文案（不调模型直接返回，省成本且稳定）；
  - [ ] 高危症状词触发固定就医提示前置（FR-K1 护栏），回答附免责声明；
  - [ ] 回答附免责声明「AI 生成内容仅供参考」；对话页入口有 AI 标识（平台合规）。

### FR-K6 供应商注册表（配置驱动接入） `P1`｜依赖：K1、J7｜闭环：L1–L3（模型层运营载体）
- 描述：`ai_providers` 表作为供应商事实源（name 唯一、base_url、note、enabled），管理端 CRUD（FR-J7）；**注册表不落密钥**——密钥仍按 `AI_<NAME大写>_API_KEY` 环境变量约定读取；内置 `zhipu`（GLM）/ `deepseek` / `openai` 种子行提供默认端点；密钥配置项默认空字符串占位——未配置真实密钥时应用照常启动，场景调用走降级文案。场景配置的 provider 引用注册表中「启用中」的供应商；网关端点解析顺序：场景 base_url 覆盖 > 注册表 base_url > 内置默认。
- 验收标准：
  - [ ] 注册表任意行、任何接口响应中不出现密钥字段与密钥值（代码检索 + 测试断言）；
  - [ ] 新增供应商保存后，场景配置表单的供应商下拉立即可选（数据源为注册表启用项）；
  - [ ] 供应商被禁用后，引用它的场景调用按「场景停用」同路径降级（不静默使用已下线供应商）；
  - [ ] 删除仅允许「已停用且无场景引用」的供应商（管理端与后端双重校验），否则提示先调整场景；
  - [ ] 自定义供应商未配置对应环境变量密钥时，给出含环境变量名的明确错误（最终表现为前端降级文案）。

### FR-K7 备用模型与故障转移 `P2`｜依赖：K6｜闭环：L1–L3（运行韧性）
- 描述：场景配置新增备用模型（`fallback_provider` + `fallback_model`，可空）。主模型调用失败（超时 / 上游 HTTP ≥ 400 / 响应不合法 / 密钥或端点缺失）时，自动以备用配置重试**一次**；仍失败则走既有降级文案。护栏（出域拒答、就医前置、红线替换）对备用输出同样生效；一次用户请求只消耗一次场景配额（内部重试不重复扣减）；调用记账标记 `fallback_used`。
- 验收标准：
  - [ ] 主挂备成 → 正常返回且 `ai_usage_logs.fallback_used=true`，tokens 合并记账；
  - [ ] 主备皆失败 → success=false 走降级，与现状行为一致；
  - [ ] 未配置备用时行为与现状完全一致（不引入额外请求）；
  - [ ] 配额不因故障转移重复扣减（单测覆盖）；
  - [ ] 备用输出命中红线词时同样被替换（单测覆盖）；
  - [ ] 不做自动路由/加权 AB（保持 §4 不做清单边界）。

### FR-K8 连通性自检 `P1`｜依赖：K6、J7｜闭环：运营配套
- 描述：后端新增管理接口（身份校验：GoTrue JWT 有效 + `admins` 白名单），管理端在供应商注册表与场景配置处提供「测试」按钮：以指定 provider + model（场景处为当前表单值，无需先保存）发送最小文本探针（"ping"，max_tokens ≤ 16），返回 `ok / latency_ms / error(status+message)`。
- 验收标准：
  - [ ] 非 admin 身份调用一律 401/403；
  - [ ] 探针 max_tokens ≤ 16（成本护栏），不计入用户配额；
  - [ ] 测试调用写 `ai_usage_logs`（成本可视，看板口径含测试调用，J7 说明），不写会话/分析表；
  - [ ] 失败时返回可操作的错误信息（HTTP 状态 + 上游 message，不含密钥）。

## 3. 安全与合规要求（NFR-1/NFR-2 落地）

- **提示词即医学规则载体**：场景提示词上线前经儿科医生/注册营养师审核，审核版本与日期落库（`reviewed_at`），与 FR-C2/E1 阈值同流程管理；
- **平台合规**：小程序内 AI 功能需完成平台类目声明；文本/图片在调用模型前过内容安全检测（预留 `app/core/ai_safety.py` 扩展位）；AI 生成内容固定标识；模型供应商须为已备案服务商；
- **隐私**：照片分析即弃为默认；`ai_analyses` 只存结构化结果；用户可删除自己的会话与分析记录（own delete）；注销级联删除（依赖 FR-H2 既有机制）；
- **成本护栏**：场景级配额 + 全局开关 + tokens 记账（`ai_usage_logs`），管理端可观测（FR-J6）。

## 4. 明确不做（防蔓延）

- 通用育儿百科问答（无上下文、无闭环，出域即拒答）；诊断/用药建议（红线）；宝宝照片相册/成长记录（照片最小化原则）；语音输入；AI 生成分享卡文案；多模型自动路由/加权 AB（故障转移仅主备重试一次，见 FR-K7）；非 OpenAI 兼容协议的原生 SDK 适配；流式输出（小程序端 SSE 复杂度不成比例，v1 整段返回）。
