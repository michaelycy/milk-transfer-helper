# 模块 E · 观察与预警

| 元素 | 内容 |
|---|---|
| 文档状态 | 草案 |
| 所属闭环 | L2 的判断层（回答"宝宝适应吗"） |
| 上游依赖 | D 记录（FR-D3 症状打卡数据、FR-D1/D2 喂养数据） |
| 下游被依赖 | C 计划（FR-C5 回退建议）、F 复盘（FR-F2 预警次数） |
| 覆盖需求 | FR-E1 ~ FR-E3 |
| 数据表 | `alerts`、`symptom_logs`（见 [03-data-model.md](../03-data-model.md)） |

## 1. 模块定位

转奶最怕的不是换奶，而是"出问题了不知道是转奶引起的、也不知道该不该停"。本模块把症状数据变成分级信号：绿色继续、黄色建议回退、红色建议就医。**定位是"观察与提醒工具"，不是诊断**（NFR-1）：所有阈值保守、所有输出带免责声明、红色预警不可关闭。

## 2. 需求明细

### FR-E1 症状信号规则引擎（可配置） `P0`｜依赖：D3｜闭环：L2
- 描述：基于打卡数据的规则集，**默认阈值上线前须经专业顾问审核，且以配置表存储可调整**。默认规则（草案）：
  - 血丝便/血便 → 红色；
  - 稀水样便当日 ≥3 次或较基线明显增多持续 2 日 → 黄色；
  - 湿疹明显加重或新发皮疹 → 黄色；
  - 频繁呕吐/发热相关主诉 → 红色；
  - 连续 2 日总奶量低于参考量 70% → 黄色。
- 验收标准：
  - [ ] 规则与阈值存于配置表，改阈值不改代码；
  - [ ] 每次评估结果落库 `alerts`（可追溯"当时为什么预警"）；
  - [ ] 规则引擎为纯函数（输入：打卡+喂养数据；输出：预警级别与依据），单测覆盖全部规则分支（NFR-5）；
  - [ ] 基线 = 计划开始前 3 个喂养日的打卡与奶量（定义见 00-glossary §1/§4）；基线不足时，相关"较基线"规则自动降级为配置表中的绝对阈值分支，并在 `payload` 记录降级原因；
  - [ ] 奶量参考规则在无体重时降级为月龄档位参考（FR-F3）；月龄与体重皆不可得时跳过该规则并记录 skipped（禁止静默失败，00-glossary §4）。

### FR-E2 分级预警 `P0`｜依赖：E1｜闭环：L1/L2
- 描述：三级呈现——🔴 红色：暂停记录新奶，建议就医（文案模板固定，不可关闭，含免责声明）；🟡 黄色：建议暂停/回退（跳转 FR-C5）；🟢 正常：无打扰。
- 验收标准：
  - [ ] 红色预警展示后无法被"忽略"跳过（只能确认已读）；
  - [ ] 所有预警文案不含诊断与药物建议（NFR-1）；
  - [ ] 预警级别以图标+文字+颜色三重传达（NFR-6 色觉友好）；
  - [ ] 预警响应率（北极星护栏指标）可统计；
  - [ ] 预警生命周期 `new → acked → resolved` 按 00-glossary §3 执行：acked 必填 `acked_at`；同规则连续 3 个喂养日无触发自动 resolved；计划终态时未决预警批量 resolved；预警只可关闭不可删除；
  - [ ] 响应率口径 = `level=red` 且 `acked_at − created_at ≤ 24h` 的占比（glossary §5），所需字段已在 03 §1 `alerts` 表定义。

### FR-E3 适应度小结 `P1`｜依赖：E1、F1｜闭环：L2
- 描述：每日/每周小结（绿/黄/红 + 关键变化："昨日大便次数 4 次，较前 7 日均值增多"），转奶期间展示在计划页。
- 验收标准：
  - [ ] 数据不足时显示"继续记录两天后生成"而非空值；
  - [ ] 小结措辞中性，不做结论性诊断表述。

## 3. 纯函数与测试要求（NFR-5）
