# 模块 D · 喂养与症状记录

| 元素 | 内容 |
|---|---|
| 文档状态 | 草案 |
| 所属闭环 | L1 执行 + L2 数据源（解决 Q2「怎么记录」） |
| 上游依赖 | H 账户（FR-H0）、A 档案（FR-A1）、C 计划（FR-D5 联动）、B 奶粉库（FR-D2 配方结构化） |
| 下游被依赖 | E 观察（FR-E1 的数据源）、F 复盘（FR-F1/F2/F3 的数据源） |
| 覆盖需求 | FR-D1 ~ FR-D5 |
| 数据表 | `feed_records`、`symptom_logs`（见 [03-data-model.md](../03-data-model.md)） |

## 1. 模块定位

记录从"流水账"升级为"适应度观察"：每顿喂养自动挂接计划（新/旧奶），每日症状打卡供规则引擎判断宝宝是否适应。**输入成本是本模块的生死线**（产品原则 3）：记一笔 ≤ 3 次触控、打卡 ≤ 30 秒，做不到则 L2 闭环没有数据可用。

兼容约束（NFR-4）：时间处理一律复用 `src/utils/date.ts`，禁止裸 `new Date('YYYY-MM-DD HH:mm')`（iOS Invalid Date 坑）。

## 2. 需求明细

### FR-D1 三秒快速记奶 `P0`｜依赖：H0、A1（有计划时依赖 C3）｜闭环：L1/L2
- 描述：首页与记录页大按钮，一键生成记录：时间=现在、配方=当前任务卡配方（有计划）或最近使用的配方（无计划）、奶量=上次同顿奶量；支持 ±10ml 大按钮微调后保存。专为夜奶单手操作设计。顿次与"同顿匹配"（±90 分钟内最近一条记录）的定义见 00-glossary §2。
- 验收标准：
  - [ ] 从点击到保存完成 ≤ 3 次触控；
  - [ ] 无历史数据时回落到完整表单（FR-D2）；
  - [ ] 记录成功有明确反馈（震动/toast）。

### FR-D2 完整记录 `P0`｜依赖：H0、A1（B1 于 M2 接入；M1 文本兜底）｜闭环：L2
- 描述：表单字段——顿次、配方（计划自动带出，可改为计划外/其他）、奶量 ml（>0）、是否喝完（喝完/剩部分/拒奶）、时间、备注。替代现有 `records` 页表单（`milk_brand` 自由文本由奶粉库选择替代，未收录时允许手动输入）。
- 验收标准：
  - [ ] iOS 时间选择无 Invalid Date（复用 `src/utils/date.ts`）；
  - [ ] 校验奶量 > 0；
  - [ ] 提交失败有可重试提示（RLS/网络错误分类文案）；
  - [ ] 里程碑口径：M1（奶粉库未上线）配方以文本输入 + 最近使用列表；M2 起接入奶粉库选择器（FR-B1），历史文本保留为 `brand_text`（迁移见 03 §3）。

### FR-D3 症状打卡 `P0`｜依赖：A1｜闭环：L2
- 描述：按日打卡，30 秒完成：大便次数与性状/颜色（提供图卡参照）、湿疹、吐奶、胀气、哭闹程度、睡眠、备注。全部可跳过，仅记奶不打卡合法。
- 验收标准：
  - [ ] 每宝宝每日一条（重复进入为编辑）；
  - [ ] 打卡数据实时供 FR-E1 规则评估；
  - [ ] 大便图卡内容需专业顾问审核（NFR-1）。

### FR-D4 记录编辑与删除 `P1`｜依赖：D1/D2｜闭环：L2
- 验收标准：
  - [ ] 删除有二次确认；
  - [ ] 编辑保留 `updated_at`。

### FR-D5 记录-计划联动 `P0`（M2，依赖计划引擎）｜依赖：C3、D1/D2｜闭环：L1/L2
- 描述：计划进行中，每条记录自动关联 `plan_id` 与当日计划配方，并标记"按计划/偏离计划"；偏离无需用户标注，由对比自动判定。
- 验收标准：
  - [ ] 计划时间轴（FR-C7）能展示每日计划内/外顿数；
  - [ ] 计划完成后记录关联不丢失（plan_id 置空策略见 03-data-model §2）。

## 3. 纯函数与测试要求（NFR-5）

- `utils/plan.ts`：`resolvePlannedFeed(plan, feedTime)` 判定某顿的"计划内配方/偏离"——纯函数 + 单测；
