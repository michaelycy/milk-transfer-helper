## 1. 模块定位

为运营侧提供奶粉库、文章审核、转奶模板的图形化维护界面与数据看板，取代「Supabase 表编辑」最小方案（B1 §3 / G1 §3 的载体升级）。**安全模型延续主应用哲学**：浏览器端只持有 anon key，管理身份 = Supabase Auth 邮箱账号 + `admins` 表白名单，写权限完全由数据库端 RLS（`is_admin()`）裁决；`service_role` 仅存在于 `admin-stats` Edge Function 服务端，永不下发到浏览器。

中立性约束（产品原则 4）在管理端同样生效：奶粉库表单与列表不提供任何推荐位、排序权重字段；文章审核只做合规流转，不做流量运营工具。

## 2. 需求明细

### FR-J1 管理员认证与白名单 `P0`｜依赖：H0（Supabase 基线）｜闭环：运营配套
- 描述：邮箱密码登录；`admins` 表为唯一事实源的白名单；登录后经 RLS 自检身份，非白名单账号立即登出并提示。首个管理员由数据库管理员手工引导（迁移文件尾部注释含步骤）。
- 验收标准：
  - [ ] 未登录访问任何后台页重定向登录页；会话失效同样重定向；
  - [ ] 非 `admins` 白名单账号登录后收到「无权限」提示且无法停留在任何后台页；
  - [ ] 浏览器端仅配置 anon key（`VITE_SUPABASE_ANON_KEY`），代码与构建产物不含 `service_role`；
  - [ ] `admins` 表 RLS 仅允许查到自己的行（无法枚举其他管理员）。

### FR-J2 奶粉库管理 `P0`｜依赖：J1、B1｜闭环：L3
- 描述：全量列表（含下架）、品牌/产品名模糊搜索、段位/蛋白类型/状态筛选；新建与编辑（品牌、产品名、段位 1–4、蛋白类型、国行/海外、注册号、成分标记、上下架）；上下架快捷切换；删除需二次确认。CSV 批量导入：模板下载、本地解析校验（错误逐行提示、全部修正前禁止提交）、按业务键（品牌+产品名+段位+版本）upsert 覆盖。
- 验收标准：
  - [ ] 特医配方（注册号 TY 开头）保存/导入时自动追加「须在医生指导下使用」标记（FR-C6 强提示数据来源）；
  - [ ] CSV 列与小程序端渲染约定一致：成分「是」→ `ingredients` 键值 `true`（客户端原样呈现键名）；
  - [ ] 重复 SKU 导入以后到者覆盖，并在完成提示中告知条数；
  - [ ] 每次保存自动维护 `updated_at`（触发器，FR-B1 验收项）；
  - [ ] 表单不出现任何推荐/排名类字段（中立性）。

### FR-J3 文章管理与审核流 `P1`｜依赖：J1、G1｜闭环：L4
- 描述：全量列表（含待审/驳回）、标题搜索与审核状态筛选；新建/编辑（标题、分类、作者、正文）；审核流转 `pending → approved / rejected`；删除需二次确认。
- 验收标准：
  - [ ] 仅 `review_status='approved'` 对小程序可见（`articles_public_read` 收紧，修复 v2 迁移遗留缺口；存量行默认 approved 无回归）；
  - [ ] 管理员可读全部状态文章（RLS `articles_admin_read`）；
  - [ ] 分类取值与小程序文章页 TAB 一致：转奶指南 / 奶粉知识 / 常见问题。

### FR-J4 转奶模板管理 `P1`｜依赖：J1、C2｜闭环：L2
- 描述：全量列表（含停用）；混合法/隔顿法的逐日节奏结构化编辑（每日 `ratio` + `label` 行编辑器，非裸 JSON）；`enabled` 停用开关；`is_default` 默认模板标记。
- 验收标准：
  - [ ] 内容（名称/方法/逐日节奏）变更时 `version` 自动 +1，进行中计划按创建时 `template_id + template_version` 锁定不受影响（03 §2.3）；
  - [ ] 同一 `method` 下 `is_default` 唯一：设为默认时自动取消同方法旧默认；
  - [ ] `ratio` 须在 0–1 区间，逐日至少 1 行。

### FR-J5 数据看板 `P2`｜依赖：J1、H4｜闭环：全部（指标消费端）
- 描述：`admin-stats` Edge Function 服务端聚合（校验调用者为 admin 后以 `service_role` 计算）：注册用户数、进行中/累计计划数、窗口期事件汇总、关键事件（`app_launch` / `feed_recorded` / `plan_created`）按日趋势、文章阅读 Top 10；窗口 7/30/90 天切换。
- 验收标准：
  - [ ] 非 admin 身份调用 `admin-stats` 一律 401/403，无数据泄露；
  - [ ] `analytics_events` 对客户端保持无 select 权限（03 §2），看板数据只能经该函数获得；
  - [ ] 指标口径与 00-glossary §5 事件清单一致，不另造口径。

## 3. 运营流程要求

- 首个管理员引导：Dashboard 建邮箱用户 → `insert into admins ...`（步骤见迁移文件尾部注释）；
- 内容发布流程（对应 G1 §3）：管理端撰写/编辑 → 顾问审核（医学正确性）→ 法务口径检查 → 置为 approved 可见。管理端提供状态流转能力，审核动作本身仍由人在流程中完成；
- 奶粉库批量更新以 CSV 导入为主通道，单条编辑用于纠错与上下架。

## 4. 明确不做（防蔓延）

用户/角色体系（单表白名单够用）、富文本编辑器（正文为纯文本 TextArea）、预警阈值配置页（配置表未落库）、条码补录队列（FR-B4 属 M4）、多语言/多租户。
